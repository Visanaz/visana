# Test Plan P0

Las suites futuras se organizarán por BR/GAP y no por clase solamente: activación, resolver por rol, Unilevel/nivel 8, team sales, pools/consistencia, restricción de rama, pagos, ledger/payout, reversals, ownership, migración y tax.

La condición de cierre de cada P0 es evidencia de prueba correspondiente en la matriz `P0_TEST_GAP_MATRIX.md`, más runtime controlado cuando dependa de infraestructura. Datos de legado deben ser sintéticos o aprobados; no se usan datos productivos sin autorización.
